# Element Anvil 0.6.0

В 0.6.0 добавлены поиск текста по проекту (Ctrl+Shift+F) и замена (Ctrl+Shift+R): регистр, слово целиком, regex, маски файлов через запятую, несохранённые буферы и просмотр diff. Выберите файлы галочками и примените изменения; Ctrl+Z отменяет их в каждом файле. Ctrl+I по-прежнему открывает структуры и методы. Кнопка «Искать» открывает полнотекстовый поиск.

При выходе с несохранёнными изменениями появляется «Сохранить / Не сохранять / Отмена». Ошибка записи оставляет редактор открытым. В дереве файлов один клик оставляет фокус для Delete (через подтверждение и корзину Windows); двойной клик переводит фокус в код. Иконки дерева уменьшены, значок обновления создан через ImageGen.

Редактор кода для Windows: 1С:Предприятие.Элемент Скрипт, проекты на диске, встроенные шрифты и необязательные аномалии.

## Возможности

- Начальное окно: открыть папку, открыть файл, создать проект из шаблона, вернуться к недавнему проекту.
- Проводник с вложенными папками. Создание файлов и папок в выбранном каталоге. Вкладки, поиск, отмена, автосохранение.
- Изменения сохраняются прямо в открытый проект. При открытии отдельного файла вне проекта его родительская папка становится проектом.
- Шесть тем: графитовая (чёрный и мягкие серые тона), янтарная, лесная, классическая Vim / консоль, морская и светлая «1С · Конфигуратор». Выбор сохраняется. Консольная тема меняет оформление, а не раскладку клавиш.
- Пять встроенных шрифтов с кириллицей: JetBrains Mono, Fira Code, IBM Plex Mono, Source Code Pro и пиксельный Press Start 2P. Интернет для их загрузки не нужен.
- Настройки шрифта, размера, темы и аномалий сохраняются между запусками. Аномалии по умолчанию выключены.
- Выделение текста подсвечивает точные совпадения в файле и на миникарте (до 2000 совпадений; выделение до 10000 символов).
- Ctrl+F открывает штатную панель Monaco с поиском и заменой: стрелки переходят между совпадениями, Enter в поле замены меняет одно, «Replace All» или Ctrl+Alt+Enter — все. Поддерживаются регистр, целые слова и регулярные выражения.
- Ctrl+I открывает поиск структур и методов во всех `.sbsl` проекта, включая несохранённые редактором изменения. Введите имя, структуру или часть пути; ↑/↓ и Enter выбирают объявление. Индекс ограничен 2000 файлами / 16 МБ / 10000 символами; при ограничении показывается сообщение.
- Настройки → «Горячие клавиши»: 25 команд можно переназначить, отключить Backspace или сбросить. Конфликты проверяются, сочетания сохраняются и работают при русской раскладке по физическим клавишам.
- У HTTP-коллекции есть сохраняемая заметка рядом с базовым URL. Она не отправляется серверу.

## Приложение Windows

В 0.5.0 файлы и папки можно перетаскивать между каталогами в проводнике редактора. Для переноса в корень бросьте элемент на заголовок проекта или пустую область списка. Совпадение имени не перезаписывает существующий файл; пути открытых вкладок, точки останова и entry обновляются. Директивы импорта автоматически не переписываются.

Изменения на диске отслеживаются через события ОС: дерево обновляется автоматически, чистые открытые файлы перечитываются, а несохранённый буфер сохраняется при внешнем перемещении или конфликте. При конфликте автосохранение этого буфера приостанавливается до явного сохранения. Структурные изменения сопоставляются по идентификаторам файлов; неоднозначные hard link показываются как создание/удаление. Предел индекса наблюдения — 20000 элементов, в более крупных проектах дерево обновляется без сопоставления перемещённых вкладок.

Ctrl+F12 открывает импортированный модуль по директиве `#требуется` или его имени перед точкой. Shift+F12 на методе показывает места использования через LSP, включая другие модули проекта. Кнопка «Искать» открывает поиск по проекту. Git diff отображается в рабочей области вкладки Git: выберите файл в списке изменений или нажмите «Diff» для текущего файла. Рабочая версия сравнивается с индексом, индекс — с HEAD. Несохранённые изменения сравниваются без записи на диск. «К коду» возвращает редактор.

Общая кнопка «Остановить» завершает обычный запуск или отладку, а во вкладке терминала — текущую терминальную сессию. Крестик терминала и закрытие его панели завершают PowerShell и дочерние процессы, включая запущенный executor. Сворачивание панели оставляет терминал работающим. Подготовку запуска также можно отменить.

Иконки папок, файлов Элемента, панелей и основных команд созданы встроенным ImageGen; оригиналы и полные промпты перечислены в [docs/ui-icons.md](docs/ui-icons.md).
Папка, файл Элемента, HTTP-клиент и поиск используют новый увеличенный набор ImageGen с единым янтарным цветом. В меню файла по ПКМ есть «Удалить…» с перемещением в корзину Windows. Сохранение больше не сбрасывает Ctrl+Z и открытые подсказки; члены текущей структуры дополняют нативный ответ LSP при вызове без `этот.`. Контекстное меню следует всем шести темам, включая меню в Shadow DOM Monaco. Причины и детали: [docs/editor-fixes.md](docs/editor-fixes.md).

Собранный файл находится в `release/ElementAnvil-0.6.0-Portable.exe`. Это переносимое приложение: установка Node.js и запуск браузера пользователю не нужны. Закройте старую версию перед запуском новой.

Настройки и список недавних проектов находятся в `%APPDATA%/Undertow/state.json`. Исходные файлы остаются в выбранных пользователем папках. Логи, кэши и снимки запуска хранятся в `%APPDATA%/Undertow/.runtime/`.

Новая версия начинает работу со стартового окна. Рабочая папка старого прототипа, если она существует, показывается в недавних проектах.

Для открытия `.sbsl` через редактор используйте `release/ElementAnvil-0.6.0-Setup.exe`: установщик регистрирует приложение для этого типа файлов. В Windows выберите «Открыть с помощью → Element Anvil» и при необходимости включите постоянное открытие. Portable EXE также принимает путь к `.sbsl` в командной строке. Файл, открытый повторным запуском, передаётся в уже работающее окно.

Setup добавляет в Проводник пункт «Открыть в Element Anvil» для папки и её фона. В Windows 11 он может находиться в «Показать дополнительные параметры». Portable поддерживает `--open-folder "C:\Путь к проекту"`; повторный запуск передаёт папку существующему окну.

Название изменено, но папка настроек `%APPDATA%/Undertow` сохранена для совместимости. Версия отображается в настройках.

Редактор называется **Element Anvil**. Название выбрано пользователем; идентификатор установки сохранён для обновления существующего приложения. Иконка создана встроенным ImageGen; исходник и точный промпт описаны в [docs/branding.md](docs/branding.md). В сборку входят PNG и ICO с размерами от 16 до 256 px.

Проводник: перетаскивание правой границы меняет ширину, Ctrl+B скрывает и возвращает панель. Вывод и ошибки: верхняя граница меняет высоту; кнопки сворачивают, разворачивают и закрывают панель; Ctrl+J возвращает её. Размеры и состояние сохраняются. Колёсико мыши закрывает вкладку файла; белая точка означает несохранённые изменения до автосохранения.

## Проекты

### 1С:Элемент Скрипт

Шаблон содержит `Скрипт.sbsl`, отдельный модуль `Модули/Приветствие.sbsl`, `unexplored.json`, README и `.gitignore`. Нужна установленная среда выполнения Элемента. Проверено на версии 10.0.4+21 и Java 17.

```text
executor.cmd Скрипт.sbsl
```

### 1С:Элемент · Веб-приложение

При каждом создании проекта редактор клонирует актуальный [1C-Element-Web-Server](https://github.com/CosmosDevX/1C-Element-Web-Server) через `git clone --depth 1`. Нужны установленный Git и интернет. Клонированные исходники не изменяются; добавляется только `unexplored.json` с точкой входа, серверным режимом и номером полученного коммита. Старой встроенной копии и автономного fallback больше нет. При ошибке клонирования показывается ошибка. F5 запускает сервер, кнопка «Остановить» завершает процесс. Текущая версия фреймворка использует `&` и ожидание соединения без тайм-аута.

`unexplored.json` указывает точку входа (старый `undertow.json` также поддерживается):

```json
{
  "language": "sbsl",
  "entry": "Скрипт.sbsl"
}
```

F5 запускает точку входа проекта, в том числе когда открыт вспомогательный файл. При отсутствии точки входа запускается текущий `.sbsl`.

Каждый запуск использует отдельный снимок проекта, поэтому дальнейшие изменения файлов не меняют выполняемый код. Служебные каталоги `.git`, `node_modules`, `release`, `.runtime`, `.zig-cache` и `zig-out` в снимок не попадают. Предел снимка — 128 МБ и 10000 файлов; предел обычного запуска — 60 секунд. Для веб-проекта с `"runMode": "server"` лимит времени отключён; есть ручная остановка. Интерактивный ввод программе пока не передаётся.

## Подсказки

Для Элемента используется существующий LSP-сервер из установленной среды: контекстные подсказки, справка, сигнатуры, переход к определению и форматирование. Компоненты 1С не включены в репозиторий или приложение и остаются в установленном пользователем комплекте. Ошибки и предупреждения приходят от LSP во время редактирования: подчёркиваются в коде и отображаются на вкладке «Ошибки». После исправления отметки снимаются. Сервер получает текущий текст, включая несохранённые изменения. Нужны установленные Элемент и Java; при отсутствии LSP проверка недоступна.

Нестандартные пути задаются переменными окружения:

| Переменная     | Назначение                                       |
| -------------- | ------------------------------------------------ |
| `ELEMENT_HOME` | Корень комплекта Элемента с `executor/` и `ide/` |
| `JAVA_HOME`    | JDK/JRE, также ищется `java` в PATH              |

## Работа с кодом и Markdown

Миникарта кода включена по умолчанию и отключается в настройках. Выбор сохраняется между запусками.

Для `.sbsl` под проводником отображается дерево «Структура файла»: структуры, их поля и методы, вложенные структуры и методы модуля. Нажатие переносит курсор к объявлению. Дерево обновляется при редактировании, комментарии, строки и локальные переменные методов не включаются. Это локальный обзор текущего файла; LSP для него не нужен.

Для `.md` в панели редактора доступна кнопка «Просмотр Markdown» / «К исходнику». Поддерживаются заголовки, списки, таблицы, блоки кода и локальные изображения PNG/JPEG/GIF/WebP до 2 МБ. Ссылки внутри проекта открывают файлы редактора, HTTP/HTTPS-ссылки открываются во внешнем браузере. Произвольный HTML не исполняется; удалённые изображения автоматически не загружаются.

## HTTP-клиент

HTTP — пятая вкладка общей боковой панели рядом с Файлами, TODO, Git и Отладкой. Коллекции отображаются слева, запрос и ответ — в основной рабочей области; введённые данные сохраняются при переключении. В настройках можно скрыть дополнительную кнопку HTTP в верхней панели. На стартовом экране есть отдельный вход в личную коллекцию без открытия проекта.

Кнопка «⇄ HTTP» открывает встроенный клиент. Без проекта доступна личная коллекция; в проекте запросы сохраняются в `unexplored.http.json`. Поддерживаются вложенные папки, переименование, перемещение запроса в другую папку, удаление с отменой и автоматическое сохранение.

У запроса можно задать HTTP-метод, базовый URL и путь (либо полный URL), параметры пути `/users/{id}` или `/users/:id`, параметры строки запроса, заголовки, текстовое/JSON-тело и тайм-аут. Параметры включаются и выключаются отдельно. Веб-шаблон Элемента получает примеры GET/POST/DELETE со стандартным разделителем `&`. Для старых сохранённых запросов по-прежнему доступен `;`. Строка предпросмотра полного URL под запросом убрана.

Клиент отправляет запросы через настольный backend, показывает статус, время, размер, заголовки и тело ответа, форматирует JSON и умеет отменять запрос. HTML отображается текстом. GET/HEAD отправляются без тела, перенаправления показываются как отдельные ответы. TLS-сертификаты проверяются обычным способом. Ответ ограничен первыми 2 МБ; бинарный ответ представлен в Base64. Тела ответов хранятся только в памяти текущего окна.

«Запустить проект» и «Остановить проект» позволяют управлять веб-сервером из клиента. Ctrl+Enter отправляет запрос, Ctrl+S сохраняет коллекцию. Личная коллекция хранится рядом с настройками в `http-collections.json`; заголовки и тела запросов входят в сохраняемую коллекцию.

Сборки 0.6.0 находятся в `release/ElementAnvil-0.6.0-Portable.exe` и `release/ElementAnvil-0.6.0-Setup.exe`.

## Файлы и сохранение

При наведении на файл или папку появляется меню действий; его также открывают кнопка ⋯ и правая кнопка мыши. Доступны переименование, дублирование файла, показ в Проводнике Windows, копирование полного и относительного пути, открытие папки в терминале, создание вложенных файлов/папок. Переименование обновляет вкладки и точку входа, сохраняет несохранённый текст редактора и не заменяет существующий файл. Ссылки #требуется в исходниках автоматически не переписываются.

Автосохранение включено по умолчанию и отключается в настройках. При выключенном режиме Ctrl+S или кнопка сохранения записывают файл; закрытие изменённой вкладки предлагает сохранить, не сохранять или отменить. Перед запуском, отладкой и действиями Git редактор предлагает сохранить правки. Белый кружок на вкладке остаётся до сохранения.

## Терминал

В нижней панели есть вкладка «Терминал» (Ctrl+обратная кавычка). Это интерактивная PowerShell через Windows ConPTY и xterm.js: история команд, работа с каталогами, до четырёх терминалов, выделение и копирование, интерактивный ввод, Ctrl+C, изменение размеров и очистка. Новый терминал начинает работу в папке проекта; меню папки открывает его в выбранном каталоге. При смене проекта и закрытии приложения терминалы завершаются.

Если среда Элемента обнаружена, команда executor доступна сразу. Она вызывает установленную Java-среду с UTF-8 и журналами в каталоге данных редактора. Например: executor .\\Скрипт.sbsl. Это полноценная командная строка с правами текущего пользователя. Поддержка Windows требует Windows 10 1809 или новее.

## Выбор запуска

F5 запускает entry из unexplored.json (также поддерживается старый undertow.json), а если entry нет — текущий .sbsl. Кнопка со стрелкой рядом с запуском позволяет явно выполнить или отладить текущий файл либо проект. В меню любого .sbsl доступны «Запустить файл» и «Отладить файл». Подсказка кнопки показывает цель запуска; выбор отдельного файла не меняет entry.

## Отладка

Панель «Отладка» использует штатный DAP-адаптер установленного Элемента. Доступны точки останова (F9 и поле слева от строки), запуск / продолжение (Ctrl+F5), пауза, шаг с обходом (F10), заходом (F11) и выходом (Shift+F11), стек вызовов, выбор кадра/потока, локальные переменные, раскрытие объектов, наблюдение за выражениями и остановка (Shift+F5). F5 по-прежнему запускает без отладки. Во время отладки файлы доступны для чтения; после завершения редактирование возвращается. Подробности о проверенных возможностях и ограничениях — в [docs/debugging.md](docs/debugging.md).

## TODO

Панель «TODO» собирает TODO, FIXME, HACK, BUG и NOTE из комментариев проекта, включая несохранённые открытые файлы. Есть поиск, группировка по файлу, автор в форме TODO(Имя) и переход к строке. Отметки выделяются в коде и на полосе обзора; строки с текстом TODO внутри строковых литералов пропускаются. Служебные каталоги не сканируются. За один поиск проверяются до 2000 файлов / 16 МБ и отображаются до 1000 отметок; достижение лимита отмечается в панели.

## Git

Нужен установленный Git в PATH. Панель показывает ветку, счётчики опережения/отставания, рабочую папку и индекс. Можно просмотреть diff, добавить отдельный файл в индекс или убрать его оттуда, создать коммит (первая строка — заголовок, остальные — описание), посмотреть последние 20 коммитов, создать локальную ветку и переключиться на существующую, выполнить Fetch / Pull / Push. Pull использует только fast-forward; конфликты показываются в списке файлов. Перед действиями сохраняются открытые изменения. После смены ветки или Pull файлы перечитываются с диска.

Для папки без собственного репозитория доступно создание через git init. Коммиты используют имя и email из настроек Git; адрес remote и авторизацию настраивают обычными средствами Git. Смена ветки и Pull во время запуска или отладки блокируются. Действия не выполняют force-push и не удаляют пользовательские изменения.

## Разработка

Нужен Node.js 22 или новее.

```powershell
npm ci
npm start
```

`npm start` открывает Electron. При первом запуске разработчика скачивается его официальный runtime, если он ещё не установлен. В готовом Windows `.exe` он уже включён.

```powershell
npm test
npm run test:integration
npm run test:lsp
npm run test:debug
npm run test:terminal
npm run build:win
```

Модульные тесты проверяют пути, junction, защиту от перезаписи, порядок сохранений, шаблоны, настройки и LSP-протокол. Интеграционная проверка использует изолированные тестовые проекты, проверяет HTTP, шрифты и реальные языковые среды, когда они доступны. Она не меняет открытые пользователем проекты.

`npm run start:web` доступен для разработки интерфейса; открытие произвольных папок и файлов требует настольного приложения с системными диалогами. `node scripts/preview.mjs` запускает изолированную UI-демонстрацию на порту 4175 с тестовыми папками вместо системных диалогов. `npm run fonts` заново копирует шрифты из установленных пакетов Fontsource.

Исходники интерфейса находятся в `public/`, файловая модель и локальный API — в `lib/`, окно Windows — в `desktop/`. Сборки, рабочие файлы и тестовые данные исключены из Git.

Границы модулей и состав уменьшенного дистрибутива описаны в [docs/architecture.md](docs/architecture.md). `scripts/check-package.mjs <путь-к-resources/app.asar>` запускается собранным Electron с `ELECTRON_RUN_AS_NODE=1` и проверяет native PTY, executor, DAP, LSP, переносы, файловое наблюдение и Git diff на отдельных тестовых проектах.

## Аномалии

Включаются в настройках. Сущность и рассыпающиеся буквы рисуются поверх текста: модель, файлы и история отмены не меняются. Прокрутка сохраняет анимацию: буквы смещаются вместе с исходной строкой. Ввод и смена файла убирают эффект. Учитывается системная настройка уменьшения движения. Силуэт собственный, без игровых спрайтов The Broken Script.
