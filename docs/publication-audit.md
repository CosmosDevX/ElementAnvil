## Зависимости и состав сборки

Первый сетевой `npm audit` сообщил о критической уязвимости DOMPurify 3.4.15, вложенного в Monaco 0.57.0. Прямой DOMPurify проекта уже был 3.4.17. Добавлен override до прямой исправленной зависимости; итоговый сетевой audit при установке и последующий audit по локальной базе: **0 известных уязвимостей**.

В Monaco также обнаружена заранее скомпилированная копия 3.4.15: одного override недостаточно. `scripts/bundle-monaco.mjs` заменяет её фабрику исходником DOMPurify 3.4.17 перед запуском и сборкой. Скрипт проверяет ожидаемую версию Monaco и границы замены и останавливается при несовпадении. При обновлении Monaco/DOMPurify эту временную адаптацию нужно пересмотреть. Первичный источник исправления: [DOMPurify advisory GHSA-cg2g-xh64-v4q7](https://github.com/cure53/DOMPurify/security/advisories/GHSA-cg2g-xh64-v4q7).

Проверены 433 записи `app.asar`: нет профилей, `.env`, пользовательских коллекций, `.git`, рабочих проектов, JAR/Java/компонентов 1С и приватных сертификатов. Встроенный Monaco содержит исправленную фабрику. Найдены MIT проекта, THIRD_PARTY_NOTICES и 24 других файла лицензий/уведомлений; LICENSE.electron.txt и LICENSES.chromium.html также находятся рядом с EXE. Скрипты самой зависимости node-pty внутри node_modules не содержат пользовательских данных.

## Оставшиеся замечания

1. **Нестабильность поиска использований LSP.** Первый пакетный прогон вернул результат без ожидаемого вызова после изменения модуля. Полный повторный прогон прошёл. Причина не локализована; возможна гонка с индексацией. В `lib/lsp.mjs` есть ожидание диагностики/hover, но оно не доказывает готовность всех перекрёстных ссылок. Не считать проблему закрытой одним успешным повтором.
2. **Закрытие PTY.** В stderr тестов появляется `AttachConsole failed` из вспомогательного процесса node-pty после завершения оболочки. Проверки уничтожения оболочки и потомков прошли, родительский тест завершился успешно. Шум/гонка очистки остаются для отдельного исправления.
3. В одном UI-прогоне была ошибка загрузки worker Monaco; следующий прогон с журналом HTTP прошёл без неё. Устойчивый сценарий не получен; стоит проверить длительную работу и повторные открытия на чистой системе.
4. Сборки **не подписаны**: сертификат подписи не настроен. Установка обоих вариантов на чистой Windows в этой проверке не выполнялась.
5. Условия использования установленного LSP/адаптера 1С и доступность товарного знака отдельно не подтверждались. Состав пакета проверен; подробности ранее просмотренной лицензии и границы выводов — в [distribution.md](distribution.md). MIT собственного кода не разрешает автоматически любые способы использования стороннего ПО.
6. Перед настоящим следующим выпуском нужно выбрать новый номер версии/тег, чтобы не путать обновлённый кандидат с прежними файлами 0.6.3.

Локальные подробные журналы: `.runtime/source-audit.json`, `.runtime/package-audit.json`, `.runtime/package-stdout.log`, `.runtime/package-stderr.log`. Эти файлы и тестовые профили исключены из Git и дистрибутива. SHA256SUMS.txt в папке кандидата относится только к двум новым EXE.
